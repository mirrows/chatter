# Chatters 项目概述与需求文档

> 版本：v0.4　日期：2026-10-28　状态：需求已确认（Q1–Q12）；v1 已实现至 `1.0.0-rc.1`，
> 未完成项与取舍见 §3.5，里程碑状态见 §6（文件名英文，正文保持中文）

## 1. 项目概述

### 1.1 项目背景
在局域网环境（家庭、办公室、网吧、临时现场）中，经常需要在设备之间快速传输文字、图片和文件。现有方式（微信/QQ、U盘、网盘）存在外网依赖、隐私风险、大小限制或操作繁琐等问题。本项目旨在开发一款**无需服务器、无需登录、纯局域网内**的点对点传输工具。

### 1.2 项目目标
- 在同一局域网内的客户端之间实现**文字消息、图片、文件**的点对点传输。
- 零配置或极简配置即可使用（自动发现设备）。
- 传输不经过任何外部服务器，数据不出局域网。

### 1.3 目标用户
- 办公室同事之间互传文件。
- 家庭多设备（电脑、手机）之间共享内容。
- 无外网或外网受限环境下的现场协作。

### 1.4 名词解释
| 名词 | 说明 |
|---|---|
| 局域网 | 通过路由器/交换机互联的本地网络 |
| P2P | 点对点，设备直接通信，不经过中转服务器 |
| 设备发现 | 自动找到同一局域网内运行本软件的其他设备 |
| 会话 | 两个客户端之间建立的通信通道 |

## 2. 功能需求

### 2.1 设备发现与连接
- **F1** 客户端启动后自动扫描局域网，列出所有在线设备（名称、IP、在线状态）。
- **F2** 用户可自定义设备昵称；首次启动自动生成默认名（如"PC-8f3a"）。
- **F3** 支持手动输入 IP 地址添加设备（应对发现失败的场景）。
- **F4** 设备上线/下线时自动刷新列表并提示。
- **F5** 提供设备标识（如指纹/校验码），防止连错设备（可选增强）。
  - **v1 结论：不实现**（Q9），留待 v2 评估；对端身份仍以 `device_id` + 昵称标识。

### 2.2 文字传输
- **F10** 支持一对一发送文字消息，支持多行文本。
- **F11** 消息按时间排序显示，显示发送/接收状态（发送中/已送达/失败）。
- **F12** 支持复制已收到的消息内容。
- **F13** 支持发送表情符号（Unicode emoji 即可，不要求自绘表情）。

### 2.3 图片传输
- **F20** 支持选择本地图片发送（jpg/png/gif/webp/bmp）。
- **F21** 支持剪贴板截图直接粘贴发送（Ctrl+V）。
- **F22** 支持拖拽图片文件到聊天窗口发送。
- **F23** 接收方在聊天中直接预览缩略图，点击可查看原图/另存为。
  - **v1 实现**：会话卡片内联预览（≤20MB），并提供「打开文件 / 打开所在文件夹 / 另存为」；
    超过 20MB 的图片不内联预览，仍可通过上述入口查看（Q11）。
- **F24** 单张图片建议支持到 50MB（需评审）。
  - **v1 结论**：传输层不限大小（1MB 分块流式）；内联预览上限 20MB（Q11）。50MB 场景已验证传输可用性，未做 50MB 专项压测。

### 2.4 文件传输
- **F30** 支持任意类型文件的选择发送与拖拽发送。
- **F31** 不支持文件夹整体发送；用户拖入文件夹时，提示"请将文件夹压缩为 zip 后发送"。
- **F32** 大文件分块传输，**支持断点续传**（连接中断后重连可从已传进度继续）。
- **F33** 传输过程显示进度条、速度、剩余时间；支持**取消**传输。
- **F34** 接收策略：**文字和图片自动接收**；**文件需用户确认后**才开始接收。接收方可配置默认保存目录。
- **F35** 单文件大小目标 ≥ 10GB（流式传输，不整块载入内存）。
- **F36** 传输完成后校验完整性（哈希校验）。
- **F37** 仅支持一对一传输，不提供群发/广播语义。

### 2.5 会话与历史
- **F40** 本地保存聊天/传输历史（可查看、可清空）。
- **F41** 历史中的图片/文件在本地缓存目录保留，删除历史时可选择同时清理。
  - **v1 实现**：接收文件保存在下载目录（见 `02` §6）；清空历史时可选删除**下载目录内、历史记录中**的接收文件，
    目录外文件不受影响。
- **F42** 支持同时与多台设备并行会话，互不干扰。
  - **v1 实现**：每个对端独立连接与传输任务（后台并行）；界面为单会话视图 + 设备列表未读徽标，**不做分屏**（Q12）。

### 2.6 系统与设置
- **F50** 开机自启（可选开关）。
- **F51** 最小化到系统托盘，接收文件/消息时有通知提醒。
- **F52** 设置项：设备昵称、默认下载目录、端口、主题（深色/浅色）、自动接收开关。
- **F53** 多语言（首版中文，预留 i18n）。

## 3. 非功能需求

### 3.1 性能
- 局域网千兆环境下传输速率 ≥ 50MB/s（目标值，需测试确认）。
  - **v1 实测（2026-10-28，本机 loopback、release 构建）**：256 MiB 文件 **36.6 MiB/s**
    （包含发送端 sha256 预计算、接收端边收边校验与杀软实时扫描），**未达目标值**；
    需在「真实两机千兆网络 + 关闭实时扫描」条件下复核后再定论（见 `11-acceptance-checklist.md` F35）。
- 设备发现响应 ≤ 3 秒；消息送达感知 ≤ 1 秒。
  - **v1 实测**：启动后 3 秒内可发现对端；文字 ACK 往返 <1 秒（局域网）。
- 传输大文件时 UI 不卡顿（网络 IO 与界面隔离）。
  - **v1 实现**：Rust 侧独立任务 + 前端进度事件按 100ms 节流。

### 3.2 安全性
- 所有数据仅在局域网内点对点传输，不经过外网。
- v1 支持传输内容哈希校验；**v1 不做传输层加密**，后续版本视需求加入。
- 文件接收默认需用户确认，防止恶意文件轰炸；文字与图片自动接收。

### 3.3 兼容性
- **v1 平台：Windows 10/11 x64。**
- **后续版本：macOS、Linux、Android**（iOS 不在计划内）。技术选型与协议设计必须保证跨平台可移植。

### 3.4 可用性
- 无需注册、无需账号、无广告。
- 断网/对方离线时有明确提示；网络恢复后可自动重连。
  - **v1 实现**：断网/离线有明确状态与失败提示；发送时自动建连，失败后可手动「重试」；
    **自动重连延后到 v2**（Q10）。

### 3.5 v1 未完成与已知取舍（对应 `1.0.0-rc.1`）

| 类别 | 项 | 说明 |
|---|---|---|
| 未实现 | F5 设备标识（指纹/校验码） | 可选增强，v1 不做（Q9） |
| 未实现 | 3.4 自动重连 | v1 用「手动重试」替代（Q10） |
| 部分满足 | F24 大图预览 | 传输不限大小，内联预览 ≤20MB（Q11） |
| 部分满足 | F42 并行会话形态 | 后台并行收发，界面无分屏（Q12） |

## 4. 已确认事项

| 编号 | 问题 | 结论 |
|---|---|---|
| Q1 | 目标平台 | 跨平台：Windows / macOS / Linux / Android；**v1 仅做 Windows**；iOS 不做 |
| Q2 | 群组/广播 | 不需要，仅一对一 |
| Q3 | 大文件与文件夹 | v1 支持大文件分块+断点续传；不支持文件夹，拖入文件夹时提示压缩为 zip |
| Q4 | 接收策略 | 文字、图片自动接收；文件需确认后接收 |
| Q5 | 历史存储 | v1 明文本地存储，可查看、可清空 |
| Q6 | 技术栈 | **Tauri 2.x + Vue 3 + Rust 后端**（已确认，Rust 网络层可复用到 macOS/Linux/Android） |
| Q7 | 传输加密 | v1 不加密 |
| Q8 | 大文件续传 | v1 提供**简版续传**（仅记录已传字节数，重连后从偏移继续）；v2 完善为块级校验的完整续传 |
| Q9 | 设备标识（F5） | **v1 不做**；v2 视需要增加（如 `device_id` 短码 + 首次连接核对） |
| Q10 | 自动重连（3.4） | **v1 不做自动重连**：发送时自动建连 + 手动重试；v2 增加退避重连 |
| Q11 | 大图预览（F23/F24） | 传输不限大小；内联预览上限 **20MB**，更大的图片走「打开/另存为」 |
| Q12 | 并行会话形态（F42） | 后台按对端并行；界面单会话视图 + 未读徽标，**不做分屏** |

另外确认：**不做消息撤回**（仅保留传输终止/取消），**不支持传输记录导出**。

## 5. 技术选型评估（Tauri + Vue）

暂定方案：**Tauri 2.x + Vue 3**，网络层用 Rust 实现（Rust 跨平台成熟，Android/iOS 支持完善）。

| 模块 | 方案 | 难度评估 |
|---|---|---|
| 桌面 UI | Vue 3 + Vite，嵌入 Tauri WebView | 低，前端生态成熟 |
| 设备发现 | UDP 广播（自定义 discovery 协议，绑定固定端口） | 低，Rust std + tokio 即可 |
| 消息/图片传输 | TCP 长连接 + 自定义二进制协议（或 HTTP） | 中，需自行设计协议与分帧 |
| 大文件分块+续传 | Rust 端 tokio 流式读写，分块传输 + 偏移记录 | 中高，需仔细处理断点状态与校验 |
| Android 端 | Tauri 2 支持 Android；Rust 网络层可复用；UI 用 Vue 重写移动端视图 | 中高，v2 再做 |
| 系统托盘/通知 | Tauri 内置 tray + notification 插件 | 低 |
| 自启动 | Tauri autostart 插件（Windows 下注册表） | 低 |
| 文件选择/拖拽 | 前端 drag&drop + Tauri dialog 插件 | 低 |

**总体评估：** v1（Windows）开发难度**中低**，主要风险点在大文件分块续传与自定义协议的稳定性。Tauri 打包体积小（~5MB），性能优于 Electron，Rust 网络层可完整复用到 macOS/Linux/Android，与跨平台目标（Q1）契合。**用户已确认：接受 Rust 后端；v1 续传做简版（按字节偏移），v2 完善为块级校验的完整续传。**

**v1 简版续传设计：**
- 发送方/接收方各自记录传输任务的（文件名、文件大小、哈希、已传字节偏移）。
- 连接中断后重连，双方交换（文件名+大小+哈希），匹配则从已确认偏移继续，不匹配则从头开始。
- v2 增强：分块粒度校验、多任务并行、传输队列持久化。
